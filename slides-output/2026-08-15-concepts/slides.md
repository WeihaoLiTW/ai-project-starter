## 改錯了怎麼辦?

**問題**:我改壞了,想回到昨天那版
**答案**:用 git,幫你的專案存檔、隨時倒帶

名詞:
- **git** = 你電腦上的工具,幫你存檔、記錄每次改動
- **GitHub** = 把你的專案放到網路上的網站(順便幫你自動測試、備份、分享)。**git ≠ GitHub**:一個是你電腦上的工具,一個是網站
- **repository(倉庫)** = 放專案所有檔案和歷史的地方(常簡稱 repo)
- **commit(存檔)** = 把現在狀態存成一個能回去的點

例:
- 狗狗 App 飼料公式改錯、算出離譜份量 → 回上一個綠存檔點
- 排班系統改介面改壞 → git 倒回昨天能用的版本
- 想比較「改之前 vs 改之後」→ git 看得到每次改了什麼

---

## 這次改動,有沒有把之前弄壞?

**問題**:我改了一個地方,會不會不小心弄壞別的?
**答案**:用測試 + CI 自動幫你檢查

名詞:**測試** 一小段程式,自動確認某功能還是對的｜**持續整合(CI)** 每次上傳,雲端自動把全部測試重跑一遍

例:
- 狗狗 App 加記帳類別 → 體重圖表不小心壞了,測試抓到
- 改鮮食搜尋 → 洋蔥/巧克力的「危險」警告不跳了,測試守住
- 本機看起來好好的、上傳後雲端測試紅 → 環境不同,持續整合幫你抓

---

## Claude 會記得我上次講的嗎?

**問題**:我以為它記得,結果它好像忘了?
**答案**:它每次都重新開始;要它記得,靠這些現在常用的做法

名詞:**CLAUDE.md** 專案規則,它每次先讀｜**skill(技能)** 把一套做法打包,之後一句話就重用｜**外部工具連接器(MCP)** 接外部工具/資料的管道｜**memory** Claude 自帶(黑盒,少依賴)

例:
- 今天叫「員工」明天它叫「同事」 → 寫進 CLAUDE.md 就固定
- 一套「匯出報表的步驟」 → 做成 skill(技能),以後說一句就跑
- 要它連公司的 Google Sheets → 用連接器(MCP),不是靠它「記得」

---

## 上線前,怎麼確定不會出包?

**問題**:直接給別人用,萬一有錯很尷尬
**答案**:分三關,一關一關先看再上 —— dev → staging → prod

名詞:**部署(deploy)** 把程式放上網路讓人能連｜**staging** 先給自己看的測試網站｜**prod** 真正給人用的正式網站

例:
- 排班系統改完,先在 staging 自己排一輪,對了才讓同事用
- 開店評估公式改了,staging 試算幾組,對了才上 prod
- prod 壞了但 staging 沒 → 正式版沒被你當場改壞

## 你要貼的那段長 prompt,在幹嘛?

**問題**:一開始叫我複製一段話貼進去,那到底做了什麼?
**答案**:先設定好「Claude 怎麼跟你合作」,再幫你把環境裝起來

它設定的合作方式:
- 用白話講、**不問你技術問題**(要用什麼資料庫/框架,它自己決定)
- 讀寫檔、跑測試直接做;只有刪東西、給別人看才停下來問你

它幫你裝環境(本機檔位),包含:
- 檢查電腦能不能跑 → 建資料夾、複製專案範本、裝好需要的東西 → 連上 GitHub 上傳
- 中間會請你:登入/授權 GitHub、取一個專案名字、點幾個「同意」按鈕(裝外掛、開權限這些 Claude 按不到,要你點)

## Claude 要「放手」到什麼程度?

**問題**:它會不會自己亂改、亂刪東西?
**答案**:它有幾種「模式」,你選它多自動 —— 新手挑中間、危險的別用

- **Plan(計畫)**:先想好、給你看計畫,你同意才動手 → 大改動前用
- **Ask(每步問)**:每個動作前都先問你 → 最安全、最慢
- **Edit(自動改檔)**:改檔案不用一個個問,直接改 → 快;刪除、對外仍會停下來問
- **Bypass(全放行)**:什麼都不問、全自動 → 危險,**新手不要用**

→ 建議新手:平常 **Ask 或 Edit**,大改動前先 **Plan**,永遠別 **Bypass**

---

## 要真的給別人用,需要什麼?

**問題**:東西做好了,怎麼變成別人能用的?
**答案**:看你做的是**哪一種**,需要的不一樣

- **網頁服務**(排班、開店評估、狗狗 App):一台一直開的機器 + 一個網址 + 資料留得住 → 平台(如 Zeabur)一次備好
- **本機自動化**(報表整理、表格更新):不用上線,關鍵是**資料進出 + 權限**
- **手機 app**(抄經 app):要上架 App Store,是另一條路

→ 先想清楚:你的東西是哪一種

---

## 做一個工具,最容易卡在哪?

**問題**:感覺不難,但做起來就是卡
**答案**:通常卡在「資料怎麼進、怎麼出」

名詞:**進** 有 API?手填?拍照轉換?別系統有權限?｜**出** 存自己的庫?寫回別系統(權限)?產檔?

例:
- 報表自動化:結果要寫進公司雲端表格 → 有沒有權限?
- 訂單比價:市場價格從哪來 → 有沒有 API?
- 抄經 app:手寫筆跡怎麼擷取 → 觸控?拍照?
