01　git

改錯了,
怎麼辦?

你昨天還好好的,今天改一改就壞了。
有沒有辦法,回到昨天那個好的版本?

答案

git 幫你留下一連串「存檔點」

每個存檔點都是測試綠、確定能跑的。回到任何一個,都一定動得了。

先認識幾個字

git
你電腦上的工具,幫你存檔、記錄每一次改動。
GitHub
把你的專案放到網路上的網站,順便幫你自動測試、備份、分享。
git 是你電腦上的工具，GitHub 是網站，兩個不一樣。
repository倉庫，常簡稱 repo
放這個專案所有檔案和歷史的地方。
commit存檔
把現在的狀態存成一個能回去的點。

用在你的「狗狗 App」

改壞了,不用慌

飼料公式改錯、算出離譜份量?回到上一個綠的版本就好,幾秒鐘的事。

02　tests

這次改動,
有沒有把之前弄壞?

我改了一個地方,
會不會不小心把別的功能弄壞了,自己還不知道?

答案

用測試加持續整合,自動幫你把關

綠燈就是沒弄壞，紅燈當場告訴你哪裡壞了。不用自己一個個檢查。

在你的專案裡，它擋下這些

加了新功能
狗狗 App 加記帳類別，結果體重圖表不小心壞了。測試抓到。
改了搜尋
改鮮食指南，洋蔥、巧克力的「危險」警告不跳了。測試守住。
環境不一樣
本機看起來好好的，上傳後雲端測試紅了。持續整合幫你抓。

03　dev / staging / prod

上線前,
怎麼確定不會出包?

直接給別人用,萬一有錯很尷尬。

答案：分三關，一關一關先看再上

每一關都能先看再決定要不要往下。正式版不會被你當場改壞。

the whole loop

把它們串起來:一個改動的完整旅程

同一套 git、測試、環境,串起來就是這條路:改一行,一路安全地送到上線。每一步壞了,都停得下來、回得去。

04　how Claude works

Claude 會記得
我上次講的嗎?

我以為它記得,結果它好像忘了?

答案

它每次都重新開始，記憶靠你放在外面

最容易誤會的是「以為 Claude 都記得」。它像記得，是因為你把東西寫在外面讓它每次重讀。最可靠的是 repo 裡的檔案，你看得到也改得到。

05　the prompt

你要貼的那段長 prompt,在幹嘛?

它設定的合作方式

  • 用白話講，不問你技術問題
  • 要用什麼資料庫、框架，它自己決定
  • 讀寫檔、跑測試直接做
  • 只有刪東西、給別人看，才停下來問你

它幫你裝環境(本機檔位)

  • 檢查電腦能不能跑
  • 建資料夾、複製專案範本、裝好需要的東西
  • 連上 GitHub，把程式碼上傳
  • 中間請你：登入授權 GitHub、取專案名字、點幾個同意

06　how far to let go

Claude 要「放手」到什麼程度?

這套的設定：權限全放手，危險動作有一道硬規則擋著

綠燈，它直接做

  • 讀檔案、寫檔案
  • 改程式、跑測試
  • 查資料、做分析

紅燈，擋下來

  • 刪東西、砍掉歷史（一道 hook 直接擋）
  • 對外發布（上線前才問你）

刪東西這類會出大事的指令，有一道 hook 直接硬擋，不是靠 AI 自律；上線發布則在你要上 prod 時才問。所以權限開到全放手也不怕。

07　shipping it

要真的給別人用,需要什麼?

看你做的是哪一種，需要的不一樣

網頁服務排班、開店評估、狗狗 App
一台一直開的機器，加一個網址，加資料留得住。平台(如 Zeabur)一次幫你備好。
本機自動化報表整理、表格更新
不用上線，在自己電腦上跑就好。關鍵是資料進出，加權限。
手機 App抄經 App
要上架 App Store，是另一條路。

08　data in / out

做一個工具,
最容易卡在哪?

感覺不難,但做起來就是卡。

答案：通常卡在「資料怎麼進、怎麼出」

框架、畫面，AI 幫你搞定。卡住你的是資料的來源、格式、權限。做任何工具，先問這三件。

用這把尺量你的專案

報表自動化
結果要寫進公司雲端表格。有沒有權限寫進去?
訂單比價
要比市場價格。那些價格從哪來，有沒有 API?
掃收據記帳
拍張收據想自動記帳。照片上的字怎麼變成資料（要辨識）?
