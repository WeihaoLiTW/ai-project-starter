**Slide 2: 核心訊息**

**Slide 3: 改錯了怎麼辦?**
問題:我改壞了,想回到昨天那版
答案:用 git 幫專案存檔、隨時倒帶
名詞:git=你電腦上存檔+記錄改動的工具;GitHub=把 repo 放到網路上的網站(順便跑 CI/備份/分享),git ≠ GitHub;repo=放專案所有檔案和歷史的地方;commit=把現在狀態存成能回去的點
例:
- 狗狗 App 飼料公式改錯、算出離譜份量 → 回上一個綠存檔點
- 排班系統改介面改壞 → git 倒回昨天能用的版本
- 想比較「改之前 vs 改之後」→ git 看得到每次改了什麼

---

**Slide 4: 這次改動,有沒有把之前弄壞?**
問題:改一個地方會不會弄壞別的?
答案:用測試 + CI 自動檢查
名詞:測試=自動確認某功能還是對的;CI=每次上傳雲端把全部測試重跑一遍
例:
- 狗狗 App 加記帳類別 → 體重圖表壞了,測試抓到
- 改鮮食搜尋 → 洋蔥/巧克力「危險」警告不跳了,測試守住
- 本機好好的、上傳後 CI 紅 → 環境不同,CI 幫你抓

---

**Slide 5: Claude 會記得我上次講的嗎?**
問題:我以為它記得,結果它忘了?
答案:它每次都重新開始;要它記得,靠這些常用做法
名詞:CLAUDE.md=專案規則它每次先讀;skill=把一套做法打包一句話重用;MCP=接外部工具/資料的插頭;memory=Claude 自帶(黑盒,少依賴)
例:
- 今天叫「員工」明天它叫「同事」→ 寫進 CLAUDE.md 固定
- 一套「匯出報表的步驟」→ 做成 skill,以後說一句就跑
- 要它連公司 Google Sheets → 用 MCP,不是靠它記得

---

**Slide 6: 上線前,怎麼確定不會出包?**
問題:直接給別人用,有錯很尷尬
答案:分三關先看再上 —— dev → staging → prod
名詞:部署=把程式放上網路讓人能連;staging=先給自己看的測試網站;prod=真正給人用的正式網站
例:
- 排班系統改完,先在 staging 自己排一輪,對了才讓同事用
- 開店評估公式改了,staging 試算幾組,對了才上 prod
- prod 壞了但 staging 沒 → 正式版沒被當場改壞

**Slide 7: 你要貼的那段長 prompt,在幹嘛?**
問題:一開始叫我複製一段話貼進去,那到底做了什麼?
答案:它先設定好「Claude 該怎麼跟你合作」,再叫它裝環境
那段 prompt 幫你設定:
- 用白話講、不丟術語(第一次出現才解釋)
- 不問你技術問題 —— 要用什麼資料庫/框架,它自己決定
- 需要你決定的翻成你答得出來的(例:最多幾人同時用?給公司外的人用嗎?)
- 讀寫檔、跑測試直接做;只有刪東西、給別人看才停下來問你
- 最後:幫你裝 starter-kit,走「本機檔位」(只到本機 + GitHub,不碰部署)

---

**Slide 8: 要真的給別人用,需要什麼?**
問題:東西做好了,怎麼變成別人能用的?
答案:看你做的是哪一種,需要的不一樣
- 網頁服務(排班、開店評估、狗狗 App):一台一直開的機器 + 網址 + 資料留得住 → 平台(如 Zeabur)一次備好
- 本機自動化(報表整理、表格更新):不用上線,關鍵是資料進出 + 權限
- 手機 app(抄經 app):要上架 App Store,是另一條路
→ 先想清楚:你的東西是哪一種

---

**Slide 9: 做一個工具,最容易卡在哪?**
問題:感覺不難,但做起來就卡
答案:通常卡在「資料怎麼進、怎麼出」
名詞:進=有 API?手填?拍照轉換?別系統有權限?;出=自己的庫?寫回別系統(權限)?產檔?
例:
- 報表自動化:結果要寫進公司雲端表格 → 有沒有權限?
- 訂單比價:市場價格從哪來 → 有沒有 API?
- 抄經 app:手寫筆跡怎麼擷取 → 觸控?拍照?
